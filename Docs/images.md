# 圖片策略(階段 3)

> 目標:網站的圖是主角,但**零授權風險**。每張圖都查得到來源、作者、授權。
> 登記簿:`Docs/images.json`。圖檔:`assets/img/`。沒登記的圖不上站,`tests/test_images.py` 會擋。
> 寫於 2026-10-25。版權背景:遊戲 © Niantic(2025-05 起 Scopely 營運),皮克敏與 Mii 角色、美術、音樂 © Nintendo
> (Nintendo 官方遊戲頁版權聲明,A)。

## 1. 決策樹:這張圖能不能用?

```
這張圖是哪來的?
│
├─ 官方美術、Logo、官網圖、宣傳圖、App Store 截圖 ─────────────→ ✗ 不用
│     (Nintendo / Niantic / Scopely 版權,沒有授權給粉絲站)
│
├─ Pikipedia、Fandom、攻略站上的遊戲截圖或角色圖 ───────────→ ✗ 不用
│     (Pikipedia 的「文字」是 CC BY-SA 4.0,但遊戲截圖是任天堂版權,
│      Pikipedia 是以合理使用掛上去的,不能轉授權給我們)
│
├─ 玩家社群的圖(Reddit、FB 社團、巴哈、IG)───────────────→ ✗ 不用
│     (作者沒授權;就算作者同意,圖裡的遊戲畫面仍是任天堂版權)
│
├─ 本站原創插畫(SVG)───────────────────────────────→ ✓ 主力
│     └─ 先過第 3 節「原創界線」檢查表,全部打勾才能用
│
├─ 你自己拍的實景照(散步、街景、真的花)──────────────────→ ✓ 可用
│     └─ 畫面裡不能有手機螢幕上的遊戲畫面;不能拍到可辨識的路人臉、車牌、門牌
│
├─ Wikimedia Commons / Unsplash 等的照片 ─────────────────→ △ 逐張確認
│     ├─ CC0、Public Domain ─────────────────────────────→ ✓ 可用
│     ├─ CC BY、CC BY-SA ───────────────────────────────→ ✓ 可用,署名寫進登記簿與頁尾
│     └─ CC BY-NC、CC BY-ND、「僅供個人使用」、看不到授權頁 ────────→ ✗ 不用
│     (只收照片、植物、街景這類素材;Commons 上的遊戲截圖多半是誤標,一律不用)
│
├─ 你自己的遊戲截圖 ───────────────────────────────────→ ✗ 不用(第 4 節已決定)
│
└─ 手機系統設定截圖(iOS / Android 設定頁,無遊戲畫面)────────→ ✓ 只用在教學(第 4 節)
```

## 2. 每張圖都要登記(Docs/images.json)

| 欄位 | 說明 | 範例 |
|---|---|---|
| `file` | `assets/img/` 下的檔名 | `mascot-bud.svg` |
| `kind` | `original` / `own-photo` / `commons` / `system-screenshot` | `original` |
| `title` | 一句話說明圖是什麼 | 吉祥物芽芽(花苞狀態) |
| `author` | 作者 | PluckPi |
| `license` | 授權 | `CC BY-SA 4.0` |
| `license_url` | 授權網址 | https://creativecommons.org/licenses/by-sa/4.0/ |
| `source_url` | 原始出處;原創寫 `null` | `null` |
| `added` | 加入日 | `2026-10-25` |
| `use` | 用在哪 | 首頁互動體驗 |
| `alt` | 替代文字,用 STE100 寫:一句、主動、不比喻 | 一個花苞形狀的小生物站在地上。 |

規則:
- `license` 只能是 `CC0`、`Public Domain`、`CC BY 4.0`、`CC BY-SA 4.0`(原創圖用本站授權 CC BY-SA 4.0,跟文字一致);`system-screenshot` 例外,見第 4 節
- `kind` 只能是 `original` / `own-photo` / `commons` / `system-screenshot`;遊戲截圖測試直接擋
- `commons` 一定要有 `source_url`,而且要開過授權頁才登記

## 3. 原創插畫的界線

**可以用的元素**:葉子、花苞、花朵、花瓣、花苗、泥土、走路的腳印、彎曲的小路、圓圓胖胖的小生物、地圖格線、天氣(太陽、雨滴)。
這些是自然界與一般插畫的共通元素,不是任何人的專有設計。

**不可以**:

| 不可以 | 原因 |
|---|---|
| 描摹、重畫、改色官方皮克敏造型 | 角色造型是任天堂著作 |
| 做出「細長身體 + 頭頂一根莖 + 莖端長葉子/花苞/花」的角色 | 這是皮克敏最核心的辨識特徵,就算自己畫也會被認成皮克敏 |
| 用紅、黃、藍三色並列當主視覺 | 這三色組合是系列最常見的識別;本站主色改用珊瑚、薰衣草、薄荷 |
| 用 Pikmin / ピクミン 字標或仿它的字體 | 商標 |
| 畫洋蔥飛船、歐利瑪、Mii、官方飾品造型(例:咖啡杯帽、郵票) | 官方角色與道具設計 |
| 用官方 UI 圖示(花苗格、蘑菇圖示、步數條樣式) | 官方介面美術 |

**本站吉祥物「芽芽」的設計理由**:
- 身體本身就是一顆花苞(上尖下圓),頭頂沒有莖、沒有葉子。開心時花瓣從**身體四周整圈**展開,芽芽自己變成花心(開花狀態);刻意不把花放在頭頂,避開皮克敏「頭上開花」的特徵
- 短短胖胖、兩片葉子當手、兩隻小腳;跟皮克敏的細長身形完全不同
- 主色是蜜桃色,不是皮克敏的紅/黃/藍

**每張原創圖上站前的檢查表**(全部打勾才登記):

- [ ] 沒有「頭頂一根莖 + 莖端葉/苞/花」的角色
- [ ] 主色不是紅黃藍三色並列
- [ ] 沒有官方字標、官方 UI 圖示、官方道具或角色
- [ ] 遮住網站名稱給別人看,對方不會說「這是 Pikmin 官方圖」
- [ ] 在亮色與暗色背景都看得清楚

## 4. 需要你決定:要不要放你自己的遊戲截圖?

| 選項 | 好處 | 風險 |
|---|---|---|
| **A 不放(建議)** | 零風險;網站風格一致(全是原創插畫) | 讀者看不到「真的遊戲畫面長怎樣」,教學要靠插畫示意 |
| B 放,但每張都附說明與版權標示 | 教學最直觀(例:計步權限設定畫面) | Nintendo 指引允許「有評論的截圖」,但適用範圍寫的是影片與圖片分享平台,沒提到個人網站;任天堂或 Scopely 要求下架時要能立刻撤 |
| C 只放手機系統設定畫面(不含遊戲畫面) | 計步權限這類教學最需要圖,而系統設定畫面不是遊戲美術 | iOS / Android 介面也有版權,但用於教學說明普遍被接受;風險比 B 低 |

我的建議是 **A + C**:遊戲畫面一律用插畫示意,只有「開計步權限」這類手機系統設定才放截圖。

**已決定(2026-10-25):A + C。** 遊戲畫面一律用插畫;只放手機系統設定截圖(`kind=system-screenshot`)。
系統截圖規則:畫面裡不能出現任何遊戲畫面或遊戲圖示以外的遊戲美術;只截設定頁;清掉狀態列的個人資訊(電信商、通知);
`license` 寫「© Apple Inc.,教學說明引用」或「© Google LLC,教學說明引用」,`license_url` 填 `null`。

## 5. 格式與大小

- 插畫一律 SVG,手寫、可讀、不嵌點陣圖;單檔 ≤ 8 KB
- 照片 WebP,長邊 ≤ 1600 px,單檔 ≤ 200 KB;上傳前清掉 EXIF(含 GPS 位置)
- 檔名:英文小寫 + `-`,例 `flower-coral.svg`、`walk-park-2026-10.webp`
- 顏色寫死在 SVG 裡(`<img>` 引用時無法繼承 CSS 顏色);需要換色就另存一個檔
